## What changed

- Corporation pages now request a small summary of each sector instead of the
  full margin-rationale breakdown, which used to make up most of the page's
  data. The corporation payload drops from roughly 900 KB to about 50 KB before
  compression.
- Game data is now compressed in transit. The corporation payload is about
  8 KB on the wire instead of roughly 900 KB, and every API response over 1 KB
  benefits.
- The share-price sparkline in a corporation's masthead now asks for the last
  20 prices instead of the full 500-row chart history.
- The actions page no longer waits for state cost data before showing your
  action cards, and its campaign-fund summary no longer downloads the whole
  portfolio chart.
- The navbar and status bar share one status request per page load instead of
  each fetching the same payload.
- The campaign detail panels and the non-default profile tabs are loaded only
  when opened, so they no longer weigh on the first page view.
- Each page now downloads only the translation copy it can actually show,
  instead of every string in the game. The catalog was most of the page.
- Achievement badges no longer ship the whole icon library, and the corporation
  page loads its Finance, Operations and Ownership bodies only when opened.

## Measurements

Targets came from production `siteTrafficPageviews` over 30 days (2026-09-24 to
2026-10-23). Route families by views, with the client-reported document load
time (`loadEventEnd`, which excludes the post-hydration API waterfall):

| Route family     |  Views |    p50 |      p95 |
| ---------------- | -----: | -----: | -------: |
| `/corporation/*` | 67,043 | 810 ms | 3,703 ms |
| `/country/*`     | 57,368 | 803 ms | 3,699 ms |
| `/profile`       | 14,110 | 706 ms | 3,562 ms |
| `/actions`       | 11,284 | 827 ms | 3,907 ms |
| `/elections/*`   | 10,305 | 808 ms | 4,124 ms |
| `/market`        |  6,244 | 788 ms | 3,406 ms |
| `/portfolio`     |  5,431 | 788 ms | 4,385 ms |

Mobile is 44% of views and carries the worse tail: p50 875 ms and p95 4,688 ms
against desktop's 764 ms and 3,041 ms.

Corporation detail payload (`loadCorporationDetailView`, 16 sectors, measured
on the benchmark world in `perf_turn_baseline`):

|        |      Raw |     Gzip |  Brotli |
| ------ | -------: | -------: | ------: |
| Before | 898.3 KB | 102.9 KB | 54.6 KB |
| After  |  53.4 KB |   8.2 KB |  7.9 KB |
| Change |   -94.1% |   -92.0% |  -85.5% |

Production sent the 923 KB corporation response uncompressed. It now sends
7,804 bytes with `content-encoding: br`; the same request without an
`Accept-Encoding` header returns 54,091 bytes, so the reduction is the encoding
and not only the smaller payload.

`GET /api/corporations/:id/history` was a 429,978-byte response for the eighteen
points the masthead draws; `?sparkline=1` returns twenty two-field points.

Follow-ups measured but left for later, with their evidence recorded in the
branch's performance notes: `/profile`'s ~15 sequential query waves, RSC
prefetch for the corporation page, and scoped refetch after corporation
mutations.

### Time to content under a mobile profile

Measured on a locally built server against the benchmark world (corporation 1,
16 sectors), 4x CPU throttling and 1.6 Mbps, fresh browser context per sample,
median of three:

|        | API bytes | API ms | Time to content |
| ------ | --------: | -----: | --------------: |
| Before |   919,228 |  1,023 |       13,053 ms |
| After  |     7,804 |    878 |        8,189 ms |

That is 4,864 ms off first content for the highest-traffic page family, which
is the transfer time the uncompressed body used to cost. On an unthrottled
desktop connection the same page is unchanged (1,970 ms before, 2,080 ms after
across five samples, inside run-to-run noise), because a local connection does
not pay for the bytes. The win is the network, and mobile is 44% of traffic and
the worse tail.

### Document size after the catalog split

Transferred document bytes for a signed-in player, before and after this
release (same world, same session, one sample per route):

| Route                     | Before | After | Change |
| ------------------------- | -----: | ----: | -----: |
| `/profile`                |  93 KB | 42 KB |   -55% |
| `/actions`                |  77 KB | 29 KB |   -62% |
| `/portfolio`              |  76 KB | 25 KB |   -67% |
| `/market`                 |  78 KB | 44 KB |   -44% |
| `/elections/US-president` |  89 KB | 40 KB |   -55% |
| `/corporation/1`          |  77 KB | 48 KB |   -38% |
| `/country/us/map`         |  76 KB | 60 KB |   -21% |

The English message catalog is 239,716 bytes of JSON and 70,586 bytes gzipped.
It was almost the entire document: `/corporation/1` was 78,378 bytes gzipped
in total.

Routes not in the map still receive the full catalog, and staff never receive a
trimmed one, so an admin screen cannot lose its strings. Both facts are
asserted by tests, and `scripts/perf/page-load/missing-messages.mjs` sweeps
nineteen real routes for `MISSING_MESSAGE` in a browser (signed in and
anonymous) before this ships.

The split is safe across client-side navigation as well: the root layout only
ships the navbar and tutorial copy, and `app/template.tsx` re-supplies the rest
per route. A template is re-created on navigation, so the catalog cannot go
stale in a session.

### JavaScript removed from the top routes

First-load JS measured from the build's own route bundle stats (uncompressed):

| Route               |   Before |    After |  Change |
| ------------------- | -------: | -------: | ------: |
| `/profile`          | 2,390 KB | 1,546 KB | -844 KB |
| `/character/[id]`   | 2,397 KB | 1,553 KB | -844 KB |
| `/settings`         | 2,267 KB | 1,427 KB | -840 KB |
| `/corporation/[id]` | 1,867 KB | 1,679 KB | -188 KB |

The profile saving is one import: `AchievementIcon` resolved icons from
`import * as icons from "lucide-react"`, which defeats tree-shaking and shipped
every icon in the library (835 KB, 218 KB gzipped) to any page that can render a
badge. The catalog uses 55 icons, now imported by name.

The corporation saving is six tab bodies (`FinancialsTab`, `ProductStudio`,
`PrivateSalePanel`, `AdvertisingAgreementsPanel`, `SponsoredFundPanel`,
`BankConsoleTab`) that only render on their own tab, now loaded on demand with
the same skeleton the other tabs use. Route-specific JS fell from 172 KB to
124 KB gzipped. Opening Finance then Financials still renders the statement, and
the smoke check clicks through that path.

Two client components also stopped importing `@sentry/nextjs` as a namespace
(`PortfolioClient`, the forex currency page) and use the existing
`captureClientException` helper instead, which loads the SDK at report time.
